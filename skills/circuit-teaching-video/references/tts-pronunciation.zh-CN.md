# 技术口播：合成前的一次轻量文本整理

目标是在不了解实际听感的情况下，主动减少明显可预见的误读。只在送入 TTS 前做一次基于全文和领域语境的 spoken_text 整理，不新增默认试音、ASR、听审缓存、风险登记册或逐词用户审批。

## 三条规则

1. **主动看语境。** 通读讲稿及必要的场景/公式上下文，识别缩写、符号、材料名、单位和中英混排。本处该读字母、专名还是词义，由上下文判断；不只依赖用户提供的词表，也不机械拆读所有英文。
2. **只做有把握的等义改写。** 对含义明确的项，用自然中文或完整名称降低歧义；没有把握就保留原文。不要编造谐音，不改变数值、量纲、否定、条件、正负号、下标或公式分组。材料 Si 可在口播里写“硅”，但 SI、S_i 及数学变量必须另按定义理解，禁止全局替换。NMOS/PMOS 只有在语境允许且不丢失重要 MOS 类型信息时才展开为明确的沟道/器件名称；不保证改写后一定读得更好。
3. **只放在可关闭的引擎输入适配层。** 规范 display_text/字幕/公式保留原样，另存实际送给引擎的 spoken_text。用稳定句子/段落 ID 关联二者；可按需留少量语境别名，不建设庞大规则库。优先级为明确本地覆盖 > 有把握的语境改写 > 原文。以后更换引擎时可关闭或替换此层，不把针对某声音的处理污染显示文本。

## 默认功能指称，必要时保留符号

含义明确时用自然的功能/位置指称，例如“这对输入管”“下方的尾管”，画面和字幕仍保留 M1、M1′ 等原始编号。若功能名会混淆、需要精确区分器件或正在推导符号关系，则保留原始符号名称。不要用“艾姆”等临时谐音替换字母。

回退不等于把排版符号原样丢给 TTS 后假定都读到了。依据本处定义，把有意义的修饰写进 spoken_text：M1′ → “M1 撇”；x² → “x 的平方”；x_2 → “x 下标 2”；a_{-1} → “a 下标负一”。负号、指数、下标和撇不能因清理字符而消失。撇在器件编号中是标签区别，在已明确导数约定的式子中才读作相应阶导数；上标也先看本处约定，不能一律当幂次。复杂分组按原数学含义写成自然短语，无法确定时保留原文并标明未确认。

可选的轻量函数 `scripts/spoken_notation.py::prepare_notation(display_text, meaning)`为已确定含义的单个符号片段生成准备文本；支持明确指定 identifier、subscript、power、signed_quantity、derivative 或 literal。它不推断物理模型、不全局替换、不另建作者词典，也不要求用户逐词标注。保持 display_text 不变，把实际选择的 spoken_text 留在原节拍计划中。

文本回归可以检查撇、下标、幂和符号是否保留，但不能证明实际发音已正确。只有任务需要时才安排有明确目的的试音比较；不要把一次比较变成所有任务的固定流程。

## 时间与能力边界

实际提供商时间事件对应 spoken_text，必须通过句子/段落映射回显示字幕；改写会改变时长，不能按字符比例声称完成对齐。有效请求/音频身份应与实际 spoken_text 及引擎配置一致。缺少可用对齐证据时标 unknown，不编造词级时序。

可选 edge-tts 适配器使用普通 spoken_text，不假定可直接接受 Azure 的 sub/say-as/phoneme 标记。具体引擎按其实际版本和能力处理。

这是 best-effort 文本整理规范，不承诺所有读音正确，也不把改写或转录相符称为发音已修复。既有[音画交付检查](production-workflow.md)仍按实际可用证据报告，未完成的听看审阅保持 pending。


实际服务功能随版本变化；公开版可选适配器与边界见 [adapters](adapters.md)。
